# WorkPanelConnecter — 架构设计

> 状态：v1 设计稿（对齐全量 Roadmap 愿景）  
> 日期：2026-08-04  
> 相关：`scheduling-boundaries.md` · `connecter-cli.md` · `ROADMAP.md`

## 1. 愿景

搭建一个服务，支持**不同 WorkPanel 之间的协同调度**：

> A 服务 a 群组的 Agent/用户 → 向 → B 服务 b 群组的 Agent/用户 发送消息 / 派发跨团队任务。

Connecter 是该协同的**调度与运维 CLI 平面**；跨团队协议走 **A2A**（不新建 AT2AT）。

## 2. 总体架构

```
                    ┌─────────────────────────────┐
                    │  WorkPanelConnecter (CLI)   │
                    │  发现 / 调度 / 日志 / 刷新    │
                    └─────────────┬───────────────┘
                                  │ 仅与「协调 Agent」交互
              ┌───────────────────┼───────────────────┐
              ▼                                       ▼
┌─────────────────────────┐             ┌─────────────────────────┐
│ WorkPanel A · 群组 a     │             │ WorkPanel B · 群组 b     │
│ ┌─────────────────────┐ │   A2A       │ ┌─────────────────────┐ │
│ │ 协调 Agent (唯一)    │◄├─────────────┤►│ 协调 Agent (唯一)    │ │
│ │ 非 AI · 调度算法     │ │  Agent Card │ │ 非 AI · 调度算法     │ │
│ └──────────┬──────────┘ │  + team_meta│ └──────────┬──────────┘ │
│            │ 框架原生    │             │            │ 框架原生    │
│     工作 Agent × N      │             │     工作 Agent × N      │
└─────────────────────────┘             └─────────────────────────┘
```

### 2.1 角色

| 角色 | 部署位置 | 性质 | 职责 |
|------|----------|------|------|
| **Connecter** | 独立进程 / CLI | 非 AI | 发现在线服务与群组；发起跨群组调度；查日志/状态；预留运维命令 |
| **协调 Agent（Team Coordinator）** | 每个 WorkPanel **恰好 1 个** | **非 AI**，纯调度算法 | 对外 A2A；对内拆解/调度成员；聚合结果；统一对外状态 |
| **工作 Agent** | 同 WorkPanel 内 | AI / 业务 | 执行具体任务；**不对 Connecter 暴露** |

### 2.2 协议选择

- **跨团队**：基于现有 **A2A** 扩展（工业落地主流；兼容原生 Agent Card）。
- **不新建 AT2AT**。
- **团队内部**：协调 Agent → 工作 Agent 使用 **WorkPanel 框架原生机制**，不走 A2A。

## 3. 协调 Agent 行为

1. **对外只暴露协调 Agent**；发布标准 Agent Card，兼容原生 A2A。
2. 接收跨团队任务 → 对内拆解并调度本团队成员 → 聚合结果 → 统一对外状态上报。
3. 在 A2A 消息 / Agent Card 中扩展 **`team_metadata`**，描述：
   - 团队能力
   - 成员清单（对内可见粒度；对外可做脱敏）
   - SLA
   - 权限边界
4. 协调 Agent **不可用 ⇒ Connecter 判定该次调度失败**（不直连工作 Agent、不旁路）。

## 4. Connecter 交互原则

1. Connecter **只与各 WorkPanel 上的协调 Agent 交互**。
2. 纯 **CLI**，无网页端。
3. 不解析业务语义；prompt / 消息正文对 Connecter 为不透明载荷，经协调 Agent 转发。
4. 调度记录、在线状态属于调度平面元数据，由 Connecter 本地（或约定存储）保留，供 `/show-log` 等使用。

## 5. 失败与可用性

| 条件 | 行为 |
|------|------|
| 目标协调 Agent 不可达 / 心跳失败 | 调度失败，写入调度记录 |
| 协调 Agent 返回失败 / 超时 | 调度失败（可配置重试策略，默认保守） |
| 工作 Agent 失败 | 由协调 Agent 聚合后对外上报；Connecter 只见协调层终态 |
| `/refresh` 后服务或群组离线 | CLI 列表更新；已发出任务按既有终态/超时规则处理 |
